ตามรอย 1 Request: กดปุ่ม “Year 2” แล้วเกิดอะไรขึ้น?

กด ถัดไป ▶ เพื่อดูทีละขั้นว่าโค้ดวิ่งผ่านไฟล์ไหนบ้าง (ตัวอย่างจาก PBI2)

FRONTENDfrontend/index.html

ผู้ใช้กดปุ่ม <button data-year="2">Year 2</button> ในแถบ filter

FRONTENDjs/components/filter.js

initFilter() ผูก event click ไว้ → อัปเดต aria-pressed ของปุ่ม → history.pushState() เปลี่ยน URL เป็น ?yearLevel=2 โดยไม่ reload → เรียก callback ที่ main.js ส่งมา

FRONTENDjs/main.js → js/api.js

loadSchedules("2") เรียก fetchSchedules("2") — ถ้าเคยโหลด “All” มาแล้วจะ กรองจาก cache ไม่ยิงซ้ำ (TR-06) ถ้ายังไม่เคยจะยิง fetch('./api/v1/schedules?yearLevel=2')

PROXY

Request วิ่งผ่าน University proxy → Course proxy → nginx บน VM ซึ่งเห็น path /api/v1/... แล้วส่งต่อให้ container backend (port 3000)

BACKENDsrc/app.js → routes/schedule.routes.js

app.use('/api/v1/schedules', scheduleRoutes) → router วิ่งผ่าน middleware validateSchedulesQuery (ตรวจว่า yearLevel เป็น 1–4 ไม่งั้นตอบ 400) แล้วไป controller

BACKENDcontrollers/schedule-filter.controller.js → services/schedule-filter.service.js

Controller ดูว่ามี req.validatedYearLevel ไหม → เรียก service getSchedulesByYearLevel(2)

DATABASErepositories/schedule.repository.js → config/prisma.js

prisma.courseSchedule.findMany({ where: { course: { is: { yearLevel: 2 } } }, include: { course: true } }) — Prisma แปลงเป็น SQL JOIN ระหว่าง courses_schedule กับ courses

BACKENDutils/schedule.formatter.js + utils/schedule.sorter.js

แปลงแต่ละแถวให้ตรง API contract (ตัด room, เวลาเป็น "HH:MM", camelCase, null ถ้าว่าง) แล้วเรียงตามลำดับ PBI1 6 ขั้น → res.status(200).json(...)

FRONTENDjs/components/table-renderer.js

renderTable(schedules) ล้าง <tbody> แล้วสร้าง <tr data-testid="schedule-row"> ทีละแถวด้วย document.createElement — ถ้า array ว่างแสดงข้อความ empty, ถ้า error เปิด <dialog>
