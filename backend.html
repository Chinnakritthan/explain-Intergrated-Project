1️⃣ Sprint 1 — วางโครง Express + Public Schedules API (PBI 1–2)

เป้าหมาย: วางรากฐาน Express, บังคับ UTF-8, เชื่อม Prisma, ตอบ /health และ /schedules[?yearLevel] ให้ตรงรูปทรง JSON และลำดับ 6 ขั้น

ไฟล์ที่สร้างใน Sprint 1หน้าที่ละเอียด
src/server.js + src/app.jsserver.js โหลด dotenv/config บรรทัดแรกสุดแล้วเปิด port; app.js เปิด cors(), เซ็ต Content-Type: application/json; charset=utf-8 ทุก response และติด errorHandler ท้ายสุด
src/config/prisma.jsสร้าง Singleton PrismaClient ให้ทุก repository แชร์ connection pool เดียวกัน (แทนที่ config/db.js ที่เคยใช้ mysql2)
routes/health.routes.js → controllers/health.controller.jsคืน { status: "ok", team: "ip26-zap" } ให้ระบบตรวจเช็คว่า backend ทำงานอยู่
routes/schedule.routes.js → schedule-filter.controller.jsแยกการทำงาน: ไม่มี ?yearLevel เรียก schedule.service (PBI1), มี ?yearLevel=1..4 เรียก schedule-filter.service (PBI2)
repositories/schedule.repository.jsfindAll() และ findByYearLevel(n) โดยใช้ include: { course: true } JOIN ตารางวิชาในคำสั่งเดียว
utils/schedule.formatter.jsหัวใจ TR-08: ตัด room และ courseId ออก, ปั้น nested object course, และแปลง MySQL TIME ด้วย getUTCHours() เพื่อไม่ให้เวลาเพี้ยนตาม timezone
utils/schedule.sorter.jsเรียงลำดับ 6 ขั้น: yearLevel → course.id → section → day (Mon=1..Sun=7) → startTime → id โดย copy array ก่อน ([...rows]) ไม่แก้ต้นฉบับ

2️⃣ Sprint 2 — Student Profile, Fixed vs Option & Selection CRUD (PBI 4–7)

เป้าหมาย: เพิ่ม Business Logic หนัก ๆ 3 ก้อน ได้แก่ ถอดรหัสนักศึกษา 11 หลัก, คำนวณ fixed, และ CRUD ตาราง selections ด้วยเวลาจาก MySQL

ไฟล์ที่เพิ่มใน Sprint 2หน้าที่ & Logic สำคัญ
routes/student.routes.js + routes/year-level.routes.jsเปิดเส้นทาง /api/v1/students/* (6 เส้น) และ /api/v1/year-levels/:yearLevel/schedules
services/student.service.js + student.repository.jsหั่นรหัส 11 หลัก → entryYear (2 หลัก), programCode (6 หลักเทียบกับ academic_settings), studentNo (3 หลักเช็คช่วงใน student_group_ranges) คำนวณ yearLevel = (2569 % 100) - entryYear + 1
services/year-level.service.jsนับจำนวน section ต่อวิชาด้วย Map<courseId, Set<section>> แล้วตัดสิน isFixedSchedule() + กรอง ?studentGroup=A โดย ต้องเก็บ studentGroup === null ไว้ด้วย ไม่งั้น INT504 หาย!
services/selection.service.js + selection.repository.jsPBI 5–7: ตรวจว่าวิชานั้นเป็น option ของชั้นปีตัวเองจริง (validateOptionSection → 404), กันเลือกซ้ำ (409), รองรับ PUT section เดิม (200 ไม่แก้ updatedAt) และใช้ prisma.$executeRaw พร้อม UTC_TIMESTAMP(3) เพื่อใช้นาฬิกาของ MySQL จริง

ทางเลือกอื่นในการออกแบบ Backend

Express 4 (ปัจจุบัน): ต้องห่อ try { ... } catch (err) { next(err); } ทุก async controller
Express 5 / Fastify / Hono: ดัก async error อัตโนมัติ ไม่ต้องเขียน try/catch ซ้ำทุกฟังก์ชัน และ Fastify มี JSON Schema validation + serialization ที่เร็วกว่าในตัว
