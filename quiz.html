ซ้อมตอบให้คล่องก่อนเจออาจารย์ — ลองตอบในใจก่อนแล้วคลิกเปิดเทียบกับแนวคำตอบ

1. อธิบาย Flow ตั้งแต่ผู้ใช้คลิก “My Schedule” จากหน้าแรก จนตารางของนักศึกษาปรากฏบนหน้าจอ ผ่านไฟล์ไหนบ้าง?
  1. index.html: ลิงก์ <a href="./my-schedule.html"> พาไปหน้าใหม่ (หน้าแรกไม่เรียก Keycloak)
  2. my-schedule.html โหลด js/my-schedule-main.js → เรียก requireSignIn() ใน js/auth.js
  3. auth.js ใช้ config.js + vendor/keycloak.js ทำ keycloak.init({ onLoad: 'login-required', pkceMethod: 'S256', checkLoginIframe: false }) → redirect ไปล็อกอินที่ Keycloak แล้วกลับมาพร้อม JWT
  4. อ่าน user.name แสดงบน header และเปิดปุ่ม Sign Out
  5. เรียก my-schedule-api.js: ยิง fetchStudentProfile(studentId) ก่อน ถ้าได้ 200 ค่อยยิง fetchYearSchedules + fetchStudentSelections พร้อมกันด้วย Promise.all
  6. ส่งข้อมูลทั้งหมดให้ renderStudentTables() และ renderStudentHeader() ใน components/my-schedule-renderer.js วาดตารางทั้ง 2 ตาราง
2. ทำไมหน้า Frontend ถึงไม่แกะรหัสนักศึกษา 11 หลักเอง และไม่คำนวณว่าวิชาไหนเป็น Fixed หรือ Option เอง?

ตามสเปก PBI4 “The page computes nothing” — กฎเรื่องปีการศึกษา (academic_settings), ช่วงกลุ่ม A/B (student_group_ranges) และจำนวน section ทั้งหมดอยู่ในฐานข้อมูลฝั่ง Backend หากคำนวณบน Frontend จะเกิดการเขียน logic ซ้ำซ้อนและอาจเพี้ยนเมื่อข้อมูลเปลี่ยน หน้าเว็บจึงเชื่อค่า yearLevel, studentGroup และ fixed: true/false ที่ Backend ตอบกลับมาเท่านั้น

3. ตอนนักศึกษากดปุ่ม Select แล้วได้ Status 201 กับ 409 โค้ด Frontend จัดการต่างกันอย่างไร?
  • ได้ 201 Created: ทำ selections.push(result.data) แล้วเรียก renderStudentTables(...) ทันที — ไม่ reload หน้า และไม่ยิง GET schedules หรือ GET selections ซ้ำ (ตาม TR-06)
  • ได้ 409 Conflict (already-selected): แปลว่า state ในหน้าจอล้าสมัย (เช่น เลือกไปแล้วในอีกแท็บ) จึงเปิด <dialog id="message-dialog"> แจ้ง “This course is already in your schedule.” เมื่อผู้ใช้กด OK หรือ Esc ค่อยเรียก fetchStudentSelections(studentId) มาซิงก์รายการที่เลือกใหม่แล้ววาด 2 ตารางใหม่
4. ทำไมตอนกด Change ใน handleChange() ต้องใช้ new Map(...) มากรอง availableSections ก่อนส่งให้ showChangeDialog()?

เพราะ 1 section ของวิชาอาจมีตารางเรียนมากกว่า 1 วันต่อสัปดาห์ (เช่น เรียนทั้งวันจันทร์และวันพฤหัส → มี 2 แถวใน array schedules ที่มี course.id และ section เดียวกัน) การทำ new Map(schedules.filter(...).map(s => [Number(s.section), s])).values() เป็นการ deduplicate ตามเลข section เพื่อไม่ให้มีปุ่ม radio ของ section เดียวกันโผล่ซ้ำ 2 อันใน dialog

5. ทำไมข้อสอบ Playwright ถึงบังคับให้ใช้ <dialog> ห้ามใช้ alert() / confirm() และมีเทคนิคคุมปุ่ม Esc อย่างไร?

window.alert() และ window.confirm() เป็น native popup ของเบราว์เซอร์ที่ไม่ได้อยู่ใน DOM Tree ทำให้เทสไม่สามารถตรวจจับ element ภายใน (เช่น radio buttons, ปุ่ม Remove/Cancel) และตกแต่ง CSS ไม่ได้
ส่วนการคุมปุ่ม Esc:

  • Fatal Error Dialog (error-dialog): ใส่ closedby="none" และดัก addEventListener('cancel', e => e.preventDefault()) เพื่อ ห้ามปิด ด้วย Esc
  • Message/Confirm/Change Dialog: ดัก dialog.oncancel ให้ปิด dialog อย่างเรียบร้อย (และในเคส 404/409 ต้องเรียก callback refreshSelections ด้วยแม้จะปิดด้วย Esc!)

6. ในโค้ด Frontend Sprint 2 มีจุดไหนที่ถ้ามีเวลาเพิ่มสามารถ Refactor ให้ดีขึ้นได้อีกบ้าง?
  1. ห่อ Dialog เป็น Promise: เปลี่ยน callback ซ้อนใน showMessageDialog(msg, onConfirm) เป็น const ok = await confirmDialog(msg) จะอ่านง่ายขึ้นมาก
  2. Event Delegation: ผูก click listener บน <tbody> แค่จุดเดียวแทนการสร้าง listener ใหม่ทุกปุ่ม Select/Remove/Change ทุกครั้งที่ render
  3. ลดโค้ดสร้าง <td> ซ้ำ: ใช้ array ของ column definitions + loop (เหมือนที่ทำใน timetable-renderer.js ของ Sprint 3) แทนการเขียน document.createElement('td') 11 บล็อกติดกัน
