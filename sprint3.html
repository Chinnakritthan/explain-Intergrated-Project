ทางเลือกอื่น: ไลบรารี Validate Request

ข้อดี
  • ไม่ต้องลง dependency เพิ่ม คุมรูปแบบ errors: [{ field, detail }] ได้เป๊ะ 100%
  • อ่านตรงไปตรงมาไม่มีเวทมนตร์

🔐 PBI10 — ล็อก API ด้วย JWT + JWKS

ตอน Sprint 2 Backend ยัง “เชื่อใจ” studentId ใน URL อยู่ — พอถึง PBI10 Backend ต้อง ตรวจ Access Token ทุกครั้ง บนเส้น students/, lecturers/, year-levels/ (ส่วน health, schedules, semester เปิดสาธารณะเหมือนเดิม)

1 · Signature

ตรวจลายเซ็นด้วย public key จาก JWKS ของ Keycloak

2 · Issuer (iss)

ต้องออกโดย realm itb-csv ของวิชาเท่านั้น

3 · Expiry (exp)

Token ต้องยังไม่หมดอายุ (อายุ 1 ชม.)

4 · Client (azp)

ต้องออกให้ ip26-zap เท่านั้น! token ของทีมอื่นห้ามผ่าน

ฝั่ง Frontend: ต่ออายุ Token “ก่อน” ยิง (authFetch)

ทางเลือกอื่น: ตรวจ JWT ใน Express

ข้อดี
  • Zero dependency, เป็น ESM แท้, cache JWKS + key rotation อัตโนมัติ
  • รองรับ Web Crypto (ใช้ได้ทั้ง Node และ Edge runtime)
ข้อเสีย
  • ต้องเขียน Express middleware ห่อเอง (~50 บรรทัด)

คู่หูยุคเก่าที่พบได้บ่อยใน tutorial — ยังใช้งานได้แต่ต้องลง 2 package และจัดการ async callback + caching เพิ่มเอง ปัจจุบันคนย้ายมาใช้ jose กันมากกว่า

📅 PBI12 — ตารางเรียนรายสัปดาห์ (Weekly Timetable)

เปลี่ยนมุมมองจาก “ตารางรวมทั้งเทอม (Courses)” มาเป็น “สัปดาห์นี้เรียนวันไหนบ้าง (Weekly Timetable)” พร้อมแสดงวันหยุดและจัดการวันสอบ

1) Database: สร้าง 1,181 Sessions อัตโนมัติด้วย SQL CTE

Test Data ให้มา 3 ตารางปฏิทิน: academic_weeks (19 สัปดาห์), holidays (7 วันหยุด), exam_periods (3 ช่วงสอบ) — ส่วนตาราง sessions (1,181 แถว) ทีมเขียนสคริปต์ SQL ใน database/init.sql และ db_design/sprint3_migration.sql สร้างขึ้นมาให้เป๊ะทุก id:

ทางเลือกอื่น: สร้างตาราง sessions ด้วยอะไรดี?

ข้อดี
  • รันจบในไฟล์ init.sql เดียวตอนเปิด MySQL container ไม่ต้องรัน Node script แยก
  • เร็วมากและรับประกันความ deterministic 100%
ข้อเสีย
  • Syntax ค่อนข้างยาว อ่านยากกว่า JS สำหรับมือใหม่

เขียนและ debug ง่ายกว่า แต่ต้องจำรัน script เพิ่มหลังจาก import SQL ทุกครั้ง

2) Backend: คำนวณช่วงสัปดาห์ (จันทร์–อาทิตย์)

3) Frontend: URL Routing, Lazy Load & Week Cache

ไฟล์ my-schedule-main.js + timetable-api.js + components/timetable-renderer.js + utils/date-utils.js ทำงานร่วมกันเพื่อทำตามกฎ TR-06:

  • Lazy Fetch: เปิด ?view=courses จะไม่ยิง /sessions — เปิด ?view=timetable จะไม่ยิง /year-levels จนกว่าจะกดสลับมุมมอง
  • Week Cache: เก็บผลลัพธ์ใน sessionsCache = new Map() โดยใช้ mondayOf(date) เป็น key → กดย้อนไปดูสัปดาห์เดิมไม่ยิงซ้ำ!
  • Cache Invalidation: ทันทีที่นักศึกษา Select / Remove / Change วิชาสำเร็จ ต้องเรียก sessionsCache.clear() เพราะตารางรายสัปดาห์เปลี่ยนไปแล้ว!
  • URL Normalization: ถ้า URL มีค่ามั่ว เช่น ?view=grid&date=abc → normalizeUrlParams() ลบออกด้วย history.replaceState ไม่ให้ค้าง
  • Bangkok Timezone: getTodayBangkok() ใช้ Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Bangkok' }) เพื่อเช็คว่า “วันนี้” อยู่ในเทอมไหมตามเวลาไทยเป๊ะ (คืนรูป YYYY-MM-DD)
