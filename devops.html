ทำไมต้องใช้ Relative Path (./api/v1)?

เพราะ URL จริงอยู่ใต้ subfolder /intproj26/<TEAM-PATH>/ ถ้าเขียน /api/v1/schedules (มี / นำหน้า) เบราว์เซอร์จะยิงไปที่ bscit.sit.kmutt.ac.th/api/v1/schedules ซึ่ง 404 ทันที! การใช้ ./api/v1/... ทำให้โค้ดชุดเดียวกันรันได้ทั้งบน VM และ localhost

ทำไมมีไฟล์ frontend/serve.json?

{ "cleanUrls": false } ปิดการ redirect อัตโนมัติของ npx serve (ที่ชอบลบ .html ออกจาก URL) เพื่อไม่ให้ my-schedule.html กลายเป็น /my-schedule จนพัง redirect URI ของ Keycloak และ test!

The Gate — ด่านตรวจก่อนคิดคะแนนทุก PBI

ถ้าด่านใดด่านหนึ่งใน Gate ไม่ผ่าน “nothing new is Done” — สิ่งที่ระบบตรวจอัตโนมัติของวิชาเช็คทุกครั้ง:

หน้าเว็บต้องเรียก API ของตัวเองเท่านั้น ห้ามแอบยิงไปเรียกเว็บ/API อื่น (ยกเว้น Keycloak)

🚫 TC-TR-2 (No JS Framework)

ห้ามใช้ React, Vue, Angular, Svelte ฯลฯ (อนุญาตแค่ Vanilla JS หรือ jQuery)

🐳 VM Check (TR-02, TR-03, TR-05)

GitHub Actions CI ของทีม (.github/workflows/ci.yml)

จุดเด่นมากของ Group 43 คือไฟล์ .github/workflows/ci.yml (808 บรรทัด) ที่สร้าง Quality Gate จำลองขึ้นเองบน GitHub รันทุกครั้งที่ push หรือเปิด PR เพื่อให้มั่นใจว่าไม่ทำโค้ดพังก่อน deploy ขึ้น VM:

STEP 1–2Checkout & Setup Node.js 22

ดึงโค้ดล่าสุด พร้อมเปิด MySQL 8.4 service container ควบคู่ไปด้วยใน job เดียวกัน

STEP 3Syntax, Merge Conflict & TR-05 Compliance

รัน node --check ตรวจ syntax ของไฟล์ .js ทุกไฟล์, เช็คว่าไม่มีเครื่องหมาย <<<<<<< หลงเหลือ และตรวจว่าไม่มี JS framework ต้องห้ามใน frontend

STEP 4Import database/init.sql & Verify DB

รัน mysql --default-character-set=utf8mb4 < database/init.sql แล้ว query ตรวจจำนวนแถวของทุกตาราง (51 courses, 97 schedules, 26 lecturers, 1,181 sessions) และตรวจภาษาไทย/en-dash ว่า UTF-8 ไม่เพี้ยน

STEP 5Prisma Validate & Verify All 11 Models

รัน npm ci, npx prisma validate, npx prisma generate และทดสอบ query จริงผ่าน Prisma Client ครบทั้ง 11 model

STEP 6Mock JWKS Server & Test PBI 1–10 (Required)

เทคนิคขั้นโปร! CI ใช้ jose สร้างคู่กุญแจ RSA ชั่วคราว + เปิด HTTP server จำลอง endpoint /certs (JWKS) แล้วส่ง KEYCLOAK_JWKS_URI ให้ Backend — ทำให้ทดสอบ PBI10 ได้ทุกเคส (token หมดอายุ, azp ผิดทีม, role ผิด, แอบดู ID คนอื่น) โดยไม่ต้องพึ่ง Keycloak จริง!

STEP 7Preview Suite สำหรับ PBI 11–12

ยิงทดสอบเคส clash (แถว 93–97, acceptClash: true) และเคส weekly sessions (วันหยุด, สัปดาห์สอบ, นอกเทอม)

JOB 2Mark Production Deployment (main only)

เมื่อ merge เข้า main และผ่านทุก step จะบันทึกสถานะ deployment environment บน GitHub

🏆 ทำไมเทคนิค Mock JWKS ใน Step 6 ถึงเจ๋งมาก? สังเกตใน backend/src/middleware/auth.middleware.js ที่ทีมเขียน process.env.KEYCLOAK_JWKS_URI || ... ไว้ให้ override ได้จาก environment variable — นี่คือหลักการ Dependency Injection ผ่าน Config ที่ทำให้โค้ด security ทดสอบใน CI แบบ offline ได้ 100% โดยไม่แก้โค้ด production เลย!
