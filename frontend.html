การจัดการ State, Cache และ URL Routing

แนวคิดการคุม state ใน my-schedule-main.js คล้าย Mini-SPA โดยไม่ต้องพึ่ง Framework:

ตัวแปร Stateชนิดข้อมูลหน้าที่ล้างเมื่อไหร่?
semesterCacheObject | nullเก็บ startDate, endDate จาก GET /api/v1/semesterไม่ล้างตลอดอายุหน้า
sessionsCacheMap<weekStart, data>cache ตารางรายสัปดาห์ แยกตามวันจันทร์ของสัปดาห์นั้นล้างทันที (.clear()) เมื่อ Select / Remove / Change สำเร็จ
coursesLoadedBooleanกันไม่ให้โหลด profile + schedules + selections ซ้ำเวลาสลับแท็บกลับไปมาไม่ล้าง
schedules & selectionsArraySingle Source of Truth สำหรับวาดตาราง My Schedule + Courses to Chooseแก้ในหน่วยความจำทันทีหลัง 201/200/204; โหลดใหม่เฉพาะตอนเจอ 404/409
isBusyBooleanLock ป้องกันผู้ใช้กดปุ่มเปลี่ยนสัปดาห์/เปลี่ยนแท็บรัว ๆ ระหว่างกำลังรอ fetchปลดใน finally

เทคนิค History API (ไม่ Reload หน้า)

  • history.replaceState(): ใช้เวลา “ทำความสะอาด URL” เช่น ลบ ?yearLevel=99 หรือ ?view=grid ทิ้ง โดย ไม่สร้างประวัติใหม่ (กด Back ไม่ย้อนกลับไป URL ผิด ๆ)
  • history.pushState(): ใช้เวลาผู้ใช้กดเปลี่ยนชั้นปี, สลับแท็บ, หรือกด Previous/Next Week — ทำหลังจาก fetch สำเร็จแล้วเท่านั้น เพื่อไม่ให้ URL เปลี่ยนไปก่อนถ้า API พัง
  • window.addEventListener('popstate', ...): ใช้ใน my-schedule-main.js เพื่อรองรับปุ่ม Back/Forward ของเบราว์เซอร์

CSS & UI Contract: Apple Liquid Glass Theme

frontend/css/style.css (~1,250 บรรทัด) ออกแบบธีม Liquid Glass รองรับทั้ง Dark และ Light mode อัตโนมัติด้วย color-scheme: light dark และ CSS Custom Properties (--glass-window-bg, --glass-surface-bg)

⚡ เกร็ด Performance จาก Git History (commit 588379a) เอฟเฟกต์ backdrop-filter: blur() เยอะ ๆ บนทุกแถวตารางทำให้ scroll กระตุก ทีมจึงปรับให้ใช้ translucent surface แทนการ blur ซ้อนหลายชั้น ทำให้เลื่อนตารางได้ลื่นระดับ 120fps ขณะที่ยังผ่าน UI Contract ครบทุกข้อเพราะแยก styling ออกจาก data-testid และ semantic HTML
