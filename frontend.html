1️⃣ Sprint 1 — หน้า Guest (PBI 1 & PBI 2)

เป้าหมาย: แสดงตารางเรียนทั้งหลักสูตร + ปุ่มกรองตามชั้นปี (All / Year 1–4) โดยไม่ Reload หน้า และไม่ขอข้อมูลซ้ำ

ไฟล์ที่สร้างใน Sprint 1

ไฟล์หน้าที่เฉพาะเชื่อมกับไฟล์ไหน
index.htmlโครง Semantic HTML: <h1>, ปุ่ม filter aria-pressed, <table data-testid="schedule-table">, <dialog id="error-dialog" closedby="none">โหลด main.js, style.css
js/main.jsจุดเริ่มต้น: รอ DOMContentLoaded → เรียก initFilter() → เรียก loadSchedules()เรียก api.js, filter.js, table-renderer.js, modal.js
js/api.jsยิง GET ./api/v1/schedules[?yearLevel=] พร้อมระบบ Cache 2 ชั้นยิง HTTP ไป Backend schedule.routes.js
js/components/filter.jsอ่าน ?yearLevel จาก URL, อัปเดต aria-pressed, ใช้ history.pushState เปลี่ยน URL โดยไม่ reloadถูกเรียกโดย main.js
js/components/table-renderer.jsสร้างแถว <tr data-testid="schedule-row"> 9 คอลัมน์ (ไม่มี Room) ด้วย createElement + textContentใช้ formatters.js, modal.js
js/components/modal.jsเปิด/ปิด empty-message และเปิด error-dialog.showModal() พร้อมดัก event cancel กันกด Escถูกเรียกโดย main.js, table-renderer.js
js/utils/formatters.jsแปลง "TUESDAY" → "Tuesday", เวลา "09:30-12:30", สัปดาห์ "11-15"ถูกเรียกโดยทุก renderer

เจาะลึกกลไกสำคัญของ Sprint 1: Cache 2 ชั้นใน api.js

💡 ทำไมต้องแยกทั้ง allSchedulesCache และ yearCache? เพราะถ้าผู้ใช้เปิด index.html (โหลด All) แล้วกด Year 1 → Year 2 → Year 3 หน้าเว็บจะยิง API แค่ครั้งเดียว แต่ถ้าเปิดตรงเข้า ?yearLevel=2 ก็จะยิงขอเฉพาะ Year 2 ก่อน (ไม่โหลดข้อมูลที่ไม่จำเป็น) ผ่านกฎ TR-06 ทั้งสองกรณี!

2️⃣ Sprint 2 — Sign-in และจัดตารางเรียนนักศึกษา (PBI 3–7)

เป้าหมาย: เพิ่มหน้า my-schedule.html เชื่อม Keycloak, แสดง 2 ตาราง (My Schedule + Courses to Choose), ทำ Select / Remove / Change ด้วย <dialog> โดยไม่ Reload

ไฟล์ที่เพิ่มและแก้ไขใน Sprint 2

ไฟล์สถานะหน้าที่ใน Sprint 2
index.htmlแก้ไขเพิ่มลิงก์ <a href="./my-schedule.html">My Schedule</a> (ห้ามเรียก Keycloak ในหน้าแรก!)
js/config.js + js/auth.js + vendor/keycloak.jsใหม่Login ด้วย OIDC + PKCE S256 (requireSignIn()) และ signOut() กลับหน้าแรก
my-schedule.htmlใหม่หน้าผู้ใช้ที่ล็อกอินแล้ว: Header ชื่อ + โปรไฟล์ + ปุ่ม Sign Out, ตาราง my-schedule, ตาราง course-options และ <dialog> สำหรับ Message/Confirm/Change
js/my-schedule-api.jsใหม่รวม 6 ฟังก์ชันยิง API: fetchStudentProfile, fetchYearSchedules, fetchStudentSelections, selectCourseSection (POST), removeCourseSelection (DELETE), changeCourseSection (PUT)
js/my-schedule-main.jsใหม่คุมวงจรชีวิตหน้า: ตรวจ login → โหลด 3 API (profile ก่อน แล้ว Promise.all([schedules, selections])) → ถือ state ใน memory → อัปเดต state หลัง 201/200/204 โดยไม่ยิง API ซ้ำ
js/components/my-schedule-renderer.jsใหม่แยกแถวเป็น 2 ตาราง (My Schedule มีปุ่ม Remove/Change เฉพาะวิชาที่เลือกเอง, Courses to Choose มีปุ่ม Select และซ่อนทั้ง section เมื่อว่าง), คุม showMessageDialog() และ showChangeDialog()
serve.jsonใหม่ตั้ง "cleanUrls": false ไม่ให้ npx serve ลบ .html ออกจาก URL ตอนรัน dev/test
